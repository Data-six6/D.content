# Dataset Limitations

This document lists everything the project scope asked for that **`Data__Engagement.csv`
cannot fully support**, so the team plans the MVP around what actually exists rather than
what was assumed. Each item follows: what's missing → which feature it affects → whether it
can be engineered around → whether more data is needed → recommended simplification.

---

## 1. No actual caption/hashtag text

**Missing:** The dataset has no column containing the real written caption or the real
hashtags used. It only has `Content_Length` (a character count) and `Hashtag_Count`
(a number).

**Feature affected:** Feature 5 — Caption & Hashtag Analysis.

**Can it be engineered?** No — you cannot derive "which words/hashtags perform well" from a
character count. `Content_Length` and `Hashtag_Count` were tested against `Engagement_Rate`
in the EDA and both show a near-zero correlation (-0.06 and -0.006 respectively).

**Is additional data required?** Yes, if you want a model trained on historical caption
performance.

**Recommended simplification (what we actually built the MVP around):** Caption & Hashtag
Analysis is **not** a trainable ML feature on this dataset. Per the project's own MVP scope,
this is handled with NLP/rule-based logic or an LLM call operating directly on the user's
*typed* caption and hashtags at request time — not on historical patterns from this data.
The Content Creator vs. Business Owner distinction (different tone/style guidance) is
implemented in that same LLM/rules layer, not as a separate trained model.

---

## 2. No caption sentiment analysis grounded in real text

**Missing:** The `Sentiment` column exists (Positive/Neutral/Negative), but with no caption
text to verify it against, we cannot confirm whether it reflects a genuinely *planned* tone
the user selects before publishing, or a label generated by analyzing the (unavailable)
caption after the fact.

**Feature affected:** Engagement Prediction (uses `Sentiment` as an input) and Caption Analysis.

**Can it be engineered?** We treated `Sentiment` as a pre-publication input (the user picks
an intended tone when planning content) — this is a reasonable assumption for the MVP, but
it should be flagged to the team as an assumption, not a verified fact.

**Is additional data required?** Only if you want to validate the assumption or build
text-based sentiment analysis for user-entered captions later.

**Recommended simplification:** Keep `Sentiment` as a simple 3-option input the user selects
in the UI when requesting a prediction (matches how it's used in `07_prediction_testing.ipynb`).

---

## 3. Content_Type is platform-dependent, not universal

**Missing:** Not literally missing, but the project description implies a generic content-type
list (Video, Image, Carousel, Text) that could apply across all platforms. In reality, each
platform has its own set of formats (TikTok: Video/Duet/Stitch; Instagram: Carousel/Photo/Reel/Story;
Facebook: Live/Post/Story/Video).

**Feature affected:** Feature 4 — Content Type Recommendation; Feature 2 — Platform Comparison.

**Can it be engineered?** Yes — this is already handled. The Content Type Recommendation
logic in `03_eda.ipynb` ranks content types **within each platform** rather than globally,
which matches reality.

**Recommended simplification:** The app's content-type dropdown should be **dynamic per
platform** (only show TikTok formats when TikTok is selected), not a single shared list.

---

## 4. Weak individual feature-to-engagement correlations

**Missing:** Not a missing column, but a real limitation worth flagging: none of the
numerical pre-publish features (Hour_of_Day, Hashtag_Count, Content_Length, Month) show more
than a weak linear correlation with `Engagement_Rate` individually (all |r| < 0.07, except
Follower_Count at -0.22).

**Feature affected:** Engagement Prediction accuracy ceiling.

**Can it be engineered?** Partially — the trained model (Logistic Regression) still reaches
~71% test accuracy / 0.706 macro F1 on 3 balanced classes (33% baseline), so there is real,
usable signal once features interact (mostly via Platform, Influencer_Tier, and Category —
see notebook 06's feature importance). But this is a modest result and should be presented
to stakeholders as "clearly better than guessing, not a highly precise forecast."

**Is additional data required?** Yes, for materially better accuracy — likely actual caption
text (for NLP-derived features), historical performance of the *specific* account, and
posting cadence/frequency data, none of which exist in this dataset.

**Recommended simplification:** Present predictions with their class probabilities (as
notebook 07 does), not just a single label, so users see the model's confidence rather than
a false sense of precision.

---

## 5. No multi-post / account-level history

**Missing:** Each row is a single, independent post. There's no way to track a single
account's posting history over time, follower growth, or trend within an account.

**Feature affected:** Any feature that would benefit from "how has *this* creator performed
historically" personalization.

**Can it be engineered?** No — `Post_ID` values aren't linked to a persistent creator/account ID.

**Is additional data required?** Yes, if personalized (per-account) recommendations are
wanted in a future version.

**Recommended simplification:** All predictions and recommendations in this MVP are
population-level (based on the whole dataset's patterns for a given platform/category/tier),
not personalized to an individual account's history.

## Summary Table

| Requirement | Available? | Feature Affected | MVP Approach |
|---|---|---|---|
| Real caption text | ❌ No | Caption & Hashtag Analysis | NLP/rules/LLM on live user input, not trained |
| Real hashtag text | ❌ No | Caption & Hashtag Analysis | Same as above |
| Verified pre-publish sentiment | ⚠️ Assumed | Engagement Prediction, Caption Analysis | Treated as user-selected planning input |
| Universal content-type list | ⚠️ Platform-specific instead | Content Type Recommendation | Per-platform dynamic list/lookup |
| Strong per-feature correlation | ⚠️ Weak individually | Engagement Prediction confidence | Present probabilities, not just a label |
| Account-level history | ❌ No | Personalization | Population-level recommendations only |
| Real posting hour | ✅ Yes | Best Posting Time | Fully supported, per platform |
| Follower count | ✅ Yes | Engagement Prediction | Used as a real, moderately predictive input |
| All 3 target platforms | ✅ Yes | Platform Comparison | Fully supported |
